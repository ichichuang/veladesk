# VelaDesk 重设计概念稿 — The Helm（掌舵）

> 2026-11-09 · 状态：Chris 已授权团队全权推进（原则 7）；视觉方向由总监在设计师候选方案中拍板
> 本文是视觉设计、动效设计与工程三方的共同事实来源；落地细节仍以 `docs/architecture/` 各文档为准。
> 前置研究：redesign-research-1（12 个产品与库的灵感扫描，本文方向与其结论一致）。

## 1. 愿景与用户

**一句话：打开浏览器的第一眼，是只属于你的甲板——VelaDesk 是一张自己掌舵、自己布置、秒开的起始桌面。**

Vela 在拉丁语里是「帆」。今天的 VelaDesk 解决了「自己部署、自己整理」，但视觉上仍是一张平面网格。重设计要把它变成一艘船：有深度（空间分层）、有生命（光与水的动效）、可无限扩展（一切皆磁贴的插件织物），同时依然是本地、私有、无广告的自托管软件——好看从不以交出数据为代价。

**目标用户**

- 自托管玩家与开发者：家里跑着一台 VelaDesk，浏览器是每天的生产工具，在意数据归属、键盘效率和「这是我的桌面」的归属感。
- 受够导航站广告的中文用户：想要干净、体面、能按自己习惯整理的起始页。
- 效率与美学取向的用户：愿意花一个周末布置桌面，再把它分享出去。

**一天的使用场景（真实用户视角）**

小林是前端工程师，迷你主机上跑着 VelaDesk，手机在同一局域网：

- 早上九点打开浏览器，桌面从本地缓存秒开，晨曦场景正慢慢亮起来；⌘K 敲两个字回车，邮箱就开了。
- 整个上午待在「工作」空间；临时查的资料用命令面板直达，不必先整理桌面。
- 晚上右键切到「在家」，旧桌面退场，新空间带着尾流般的光滑进来——这是他一天里最放松的一次点击。
- 周末重排「在家」空间，装一个天气小部件磁贴，再把整张桌面导出成 `.deck.json` 发给同事。
- 躺在床上用手机打开同一个 VelaDesk，搜索、点开、看视频。

## 2. 团队已定原则

2026-11-09 起生效；以下各条不再反复讨论，直接执行：

1. **动效引擎分工**：编排型签名时刻——Orbits 缩放旅行、Wake 尾迹、拂晓开屏——归 GSAP；Motion（framer-motion）只做 React 组件状态与布局过渡、拖拽重排（FLIP）。两套引擎永远不动画同一个元素。
2. **Lenis 绝不做整页滚动**：只挂在指定的独立滚动容器上，可整体关闭；reduced-motion 下默认关闭。
3. **所有时长与缓动都是设计令牌**。reduced-motion 下：缩放旅行退化为直接切换，Wake 尾迹关闭。
4. **灵感库按需移植**：Aceternity / Magic UI / React Bits 的效果按需移植为自有组件，用 HeroUI 与自有令牌重写——颜色、圆角、模糊、光晕强度跟随主题；不整包引入库，不照搬它们的配色与样式。
5. **每个空间至多一个主签名动效**，其余一切保持安静。
6. **开屏签名时刻「Vela Dawn」**：每次新标签页，界面像黎明从海平线亮起，300ms 内完成，本地缓存先行渲染。
7. **决策权**：Chris 已授权团队全权推进；视觉方向由总监在设计师的候选方案中拍板。

## 3. 五个高光时刻

1. **开屏「拂晓 Vela Dawn」**：每次新标签页，界面像黎明从海平线亮起，300ms 内完成，本地缓存先行渲染（原则 6）；首次打开在此之上叠加引导，磁贴如升帆依次立起。reduced-motion 下直接呈现静态版。
2. **启航（打开网站）**：点击磁贴不是原地跳转——磁贴经 FLIP 共享元素过渡放大成一张鼓风的帆，再交给浏览器；指针划过桌面时留下淡淡的 Wake 尾流光迹。
3. **切换空间（Orbits）**：滚轮或捏合向后拉，桌面退远成一组轨道——每个空间是一条轨道环，常用空间在前；切换即镜头沿环滑动、各层视差，壁纸交叉淡化（沿用现有行为）。
4. **命令与搜索（⌘K）**：现有右键搜索升级为全局命令面板，像一间海图室：输入即唤出结果，磁贴按弹簧曲线错峰浮出，↑↓ 选择、回车直达；还能执行动作（打开、切空间、新建磁贴）。
5. **整理磁贴**：拖动时尾迹弯曲、邻近磁贴磁性让位，落点吸附漾开一圈涟漪；打开文件夹是磁贴到面板的 FLIP 变形。

语义缩放贯穿全部时刻：拉近看磁贴细节，中景是桌面，拉远看空间与轨道。reduced-motion 下，缩放旅行退化为直接切换、Wake 尾迹关闭；同一空间至多一个主签名动效，其余保持安静（原则 3、5）。

## 4. 个性化模型与插件架构

**个性化模型**

- **主题**：明暗模式（跟随系统）、强调色、材质风格（清爽 / 柔和 / 玻璃，演进为令牌化材质档）——全部由 `packages/ui` 的全局设计令牌驱动，组件不写死颜色与尺寸。
- **布局**：固定应用框架 + 独立可滚动容器（既定偏好）；空间内布局预设：网格 / 自由画布 / 轨道；Dock 继续承载最常用入口。
- **动态背景**：内置程序化「活场景」（极光、午夜、晨曦、薄雾升级为 WebGL），支持上传图片；性能规则：惰性加载、限帧、不可见即暂停、reduced-motion 退为静态渐变。
- **磁贴与小部件**：一切皆磁贴——应用、文件夹、小部件（时钟、天气、待办、订阅）、插件磁贴共用同一尺寸体系与交互语法。

**插件架构（概要）**

- **`vela.manifest.json`**：声明 id、名称、版本、依赖的 vela.* API 版本区间、权限、入口与磁贴规格；安装时逐项向用户展示并授权，默认全部拒绝，可随时撤销。
- **运行时**：每个插件运行在独立 iframe 沙箱（无同源权限），经 postMessage RPC 与宿主通信；插件之间互不可见；插件崩溃或超载只影响它自己的磁贴，主页面永不等待插件帧。
- **API 面（版本化 `vela.*`）**：`vela.tile`（注册磁贴与配置面板）、`vela.storage`（插件私有配额存储）、`vela.theme`（只读订阅主题令牌）、`vela.launcher`（注册命令）、`vela.desktop`（读写布局，需授权）、`vela.events`（订阅有限的应用事件）。
- **红线**：未经明确授权，插件拿不到任何标签页、浏览记录或工作区数据；网络请求仅限声明的白名单域名。
- **`.deck.json`**：整张空间/桌面的可分享快照（布局、磁贴、主题引用，不含私有数据），由现有 JSON 导入导出演进而来。

## 5. 不可妥协的工程约束

1. **秒开**：首帧由本地缓存（IndexedDB 本地副本 + 静态外壳）立即绘出，特效渐进增强加载，绝不阻塞可用。
2. **本地优先**：数据留在自己的设备（SQLite + IndexedDB），随时整体导入导出（`.deck.json`），不依赖任何云服务。
3. **插件隔离**：沙箱 + 帧预算 + 单插件开关；任何插件都不能拖慢或破坏主页面。
4. **动效**：快、可打断（新交互先 kill 旧 tween，延续现有规则）、时长与缓动完全由动效令牌驱动；共享元素过渡用 FLIP；磁贴/面板入场 ≤300ms；全量尊重 `prefers-reduced-motion`；只动 transform / opacity。

## 6. 技术栈决策

| 层 | 决策 | 理由 |
| --- | --- | --- |
| 组件库 | 保留 HeroUI v3，作为唯一组件库 | 已深度使用；遵守「一个组件库」偏好，不引入第二套 |
| 编排动效 | 保留 GSAP | 独占编排型签名时刻：Orbits 旅行、Wake 尾迹、拂晓开屏（原则 1）；时间线、Flip、ScrollTrigger；现有动效体系（`docs/architecture/motion.md`）零迁移成本 |
| 组件态动效 | 新增 Motion | 只做 React 组件状态/布局过渡与拖拽重排（`layout`/`layoutId` FLIP、`AnimatePresence`、spring），与 React 19 集成顺手 |
| 平滑滚动 | 新增 Lenis | 只挂指定的独立滚动容器，绝不整页（原则 2）；可整体关闭，reduced-motion 默认关 |
| 灵感库 | Aceternity / Magic UI / React Bits | 只按需移植为自有组件：用 HeroUI 与自有令牌重写，颜色、圆角、模糊、光晕跟随主题；不整包引入、不照搬配色与样式（原则 4） |

**迁移要点**：Motion 只在新层（scene / tile-host）引入，不回改既有 GSAP 行为；引擎分工与「同一元素不双动画」按「团队已定原则」执行；令牌迁入 `packages/ui` 后 apps/web 只消费不定义；新增依赖须守住首屏体积预算（数值由工程在 P1 基线中定）。

**既定偏好（贯穿所有决策）**：一个组件库；固定应用布局、独立可滚动容器；架构级全局设计令牌；流畅优雅、克制不炫技的动效。
